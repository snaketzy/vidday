# Vidday 产品需求与范围

基线：`dev.all-platforms@f89eeb9`，盘点日期 2026-11-23。本文区分「已实现」「拟开发」「未批准」，不以分支名称、页面按钮或历史文档代替发布证据。

## 产品目标

让观众在 Web、macOS 桌面、Android 手机和平板、Android TV 上发现和播放已上架影视内容；保证起播、进度恢复和终端交互可靠，让运营通过 QoE 衡量真实体验。轮播、影视资料及上架管理由外部管理端负责，本仓不负责内容录入、转码、上传或运营后台。

| 能力 | 当前实现 | 下一阶段验收 |
|---|---|---|
| 发现与详情 | Web/Electron 有首页、筛选、搜索、专题、影人与演员、详情；Web 搜索限已载入目录。Android 有首页、电影、剧集、最近更新、查找、详情；搜索先分页拉全目录，专题未接。 | 加载、空数据、失败、重试可区分；不将本地搜索宣传为服务端全库搜索。 |
| 播放 | Web/Electron 用 hls.js 或浏览器原生 HLS，支持 ABR、轨道、PGS、全屏、PiP、广告入口；Android 用 Media3、原生 HLS/PGS，UI 支持轨道、画质、全屏和可用时的 PiP。 | 固定 HLS 样本验证起播、拖动、切轨、弱网、离页及重进；外挂字幕失败不应阻断画面。 |
| 剧集 | 服务端详情只给一个 `playUrl`，通常取首个可播单集；Web 有选集路由但适配层不下发完整季集数据，Android 未接选集。 | 完整选集、跨集续播须先定义季/集 DTO、授权及无源行为；当前不承诺。 |
| 账户与收藏 | Web/Electron 有演示登录、档案与本地口令，片单和进度通过设备 ID 同步。Android 目前只消费内容、上报 QoE。 | 清楚说明本地与远端数据；演示账户不是认证，现状不支持跨设备共享，也不按档案隔离远端数据。 |
| 多端交互 | Web 浏览器与 Electron 复用页面，无独立 Web TV 模式；Android 手机/TV 共用工程，遥控器完整可用性待真机验证。 | TV 首页到详情至播放可用遥控器，返回恢复焦点；触屏不回归。 |
| 桌面线路 | Electron 主进程管理 Mihomo，可走系统网络或内置线路；存在未注册的独立线路页。 | 缺资源或线路失败可读地降级；不得影响普通 Web 使用。 |
| QoE | Web/Electron 现报 `web`，Android 报 `android`；后台索引、聚合与展示不在本仓。 | 定义 TTFF、卡顿、码率的统一口径；注明平台差异，样本需可复现，数据不含秘密。 |

## 拟开发及明确排除

- 两阶段规划：先恢复自动化基线并加固现有客户端，再提审平台识别、匿名用户绑定/解绑、按用户共享进度，以及低频会话汇总和分辨率分布。`x-client-platform`、`user_id` 和新遥测字段均非现行契约。
- iOS、tvOS 当前只有预设工作树，没有已跟踪工程；先立项评估 HLS、Apple 签名与发布、TV 焦点、字幕和 PiP 的能力差异。未经批准不创建工程或选定新技术栈。
- DASH、会员、支付、正式身份系统、DRM、离线下载均非当前交付范围。

技术依据与债务见 [项目分析](PROJECT_ANALYSIS.md)；执行顺序见 [任务计划](../tasks/TASK_BOARD.md)。
