# 编码规范

1. 只修改任务白名单。不要全仓格式化或顺手重构；公共名字、默认值与单位发生变化即按兼容变更办理。删除前核对静态引用、路由、IPC、测试及配置。
2. TS 按工程现有导入风格：Web `@/` 指向 `src/`，服务端相对路径保留 `.ts`，类型用 `import type`。外部数据进边界时按 `unknown` 检查或映射；不用 `any`、强制断言或忽略错误替代校验。
3. React 页面负责组合，数据通过既有 hooks/API/slices；清理 effect 的事件、计时器与过时异步响应。组件至少处理 loading、empty、error 和正常状态；控件提供可聚焦按钮、键盘/触屏行为及可读标签。
4. Dart 改动文件用 `dart format`，遵从 `analysis_options.yaml`。I/O 使用 `ApiClient`，异步回来先检查 `mounted` 或销毁标志；TV 使用方向键、确认和返回验证，不只依赖 `onTap`。Kotlin 使用现有 Gradle 风格与 Android 生命周期，耗时 I/O 不阻塞主线程；释放 `PlayerView`、线程、监听和缓存句柄，不向已释放会话发送事件。
5. 严格区分 progress 秒与媒体/遥测毫秒，变量含单位（如 `positionMs`）。每个播放源独立状态；暂停/拖动不直接当作网络卡顿。缺失未知值与零区分；保持音量、画质、轨道 ID 和 PiP 契约。
6. SQL 放在 `server/src/db/`；路由校验输入、按 `HttpError` 返回业务错误、映射 DTO。不能把数据库行、堆栈、凭证或带签名 URL 下发/记录。配置使用 `*.example` 和占位符，禁止提交真实 Key、签名、数据库密码、订阅地址。
7. 测试用合成 DTO、可控时间、媒体夹具或隔离库，而不是公网响应和生产数据。修 bug 写能复现旧行为的回归用例；测试名字描述可观察结果。
